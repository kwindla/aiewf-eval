# Recovery context and judge migration validation

Status: revised after independent Astra and Fable 5.1 review; implement under the binding dispositions below.

The current judge discards recovery exchanges before constructing its prompt. Those exchanges are extra harness prompts such as “Please go ahead.” They should not create additional scored turns, but their answers and actual tool outcomes are part of the conversation state. A confirmed example is Gemini 3.5 Flash's successful recovery support call followed by a failed judgment asserting that no ticket had been submitted.

The current published tables contain 50 text and 11 voice configurations, 1,619 complete conversations and 48,570 scripted turns. Of those conversations, 666 contain 1,375 recovery records; 609 recovery records contain tool calls. These are exposure counts, not incorrect-grade counts. The initial four-conversation calibration was deliberately selected and is not an independent accuracy estimate.

## 2. Implement complete context with unchanged scored targets

Hold contradictory, orphaned, or ambiguous records for review rather than dropping them or inventing order.

A later recovery success cannot retroactively turn an earlier missed required action into a pass. Reject judgments for recovery IDs, duplicate or missing scripted targets, nonboolean scores, and unexpected judge model/settings. The CLI should use the corrected context path for future judging.

**Scoring interpretation (Fable B5).** An already valid earlier recovery call satisfies the same later expected action under the existing early-call rule. An unnecessary deferral at a scripted turn remains a tool-use/instruction failure even if recovery later succeeds. A genuinely necessary clarification because a required argument is unavailable remains valid under the governing policy; recovery presence does not turn it into a failure. Judge the original response using information available at that time, not hindsight or literal golden wording. These are applications of the frozen policy, not a new benchmark policy. A recovery earns no judgment and cannot be relabeled as a later scripted action. Subsequent claims about tool state use the actual recorded recovery outcome.
